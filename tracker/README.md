# SDK first-party: instalação em staging

O módulo não é ativo na página original do Inglês de Embarque. O repositório não contém essa página. `examples/ingles-de-embarque.html` é um laboratório com configuração intencionalmente incompleta: não chama coletor nem navega para compra enquanto os placeholders não forem substituídos. Nenhum Pixel ou token de integração está embutido.

1. Configure um projeto **isolado**, aplique o baseline revisado + novas migrações conforme o runbook da raiz e implante `pulso-collect` nesse staging.
2. Como owner/admin autenticado, registre origem HTTPS exata, chave pública e versão de política usando `configure_tracking_site(p_workspace_id,p_site_key,p_allowed_origins,p_consent_policy_version)`. A mesma chave não pode ser atribuída a outro workspace. Origem não é prova de pessoa ou de consentimento: clientes não browser podem forjar `Origin`; mantenha limites, monitoramento e gateway contra abuso antes da ativação.
3. Substitua somente no laboratório `collectorUrl`, `publicSiteKey`, `checkoutURL` de teste e `policyVersion`. Não use o projeto de produção nessa etapa. A confirmação dos testes da Hotmart e do retorno integral do `sck` é obrigatória antes da página real.
4. Integre à CMP real. `marketingAllowed()` deve refletir a decisão atual; `consentRecord()` deve retornar o registro real da decisão, com `{marketing:true,basis:'consent',policy_version:'versao-publicada',captured_at:'ISO-8601'}`. O backend exige a versão registrada no site e captura nos últimos 24h. Não gere timestamps novos em cada evento para simular uma decisão antiga. Política/consentimento expirados exigem uma nova decisão real.
5. Chame `track('page_view')` após permissão; `track('view_content')` ao observar a oferta. Use `track('checkout_click')` no clique. **Não chame `checkout_started` por simples clique num checkout externo.** `checkout_started` exige um sinal efetivo de abertura/carregamento de checkout sob instrumentação autorizada. SDK suporta o nome para esse contrato, não fabrica esse sinal.
6. Antes de navegar, aguarde a resposta da coleta e use `checkoutHref(urlOriginal)` para links diretos HTTPS `pay.hotmart.com`. São preservados `off`, `src`, `xcod`, afiliação e todos os parâmetros existentes. **`sck` existente nunca é sobrescrito.** Marque o conflito na observação de QA: essa compra poderá ficar `unattributed` em vez de atribuir por aproximação. Links `go.hotmart.com` não são decorados; preserve-os. Checkout Elements necessita configuração e teste específico do fabricante antes da ativação; este exemplo só demonstra link externo.
7. O backend devolve um `sck` opaco HMAC de 30 caracteres alfanuméricos: limite conservador da [ajuda oficial Hotmart](https://suportehotmart.zendesk.com/hc/pt-br/articles/216441797-Como-identificar-a-origem-das-minhas-vendas-na-Hotmart) (consulta 28/10/2026). A expiração de 24h e o vínculo tenant/site/sessão ficam privados no servidor. Apenas MAC válido **e** lookup no workspace autenticado pelo Hottok autorizam associação. O teste de eco no webhook segue pendente, pois documentação legada cita limites diferentes.

## Revogação e conectividade

Ao recusar após consentir, a CMP precisa **aguardar `revokeConsent()`** e atualizar a interface com o resultado. O pedido contém apenas site e token de exclusão, sem novos sinais publicitários. O SDK limpa o token de marketing e mantém uma pendência de revogação em `sessionStorage` exclusivamente para reenvio até confirmação. Enquanto houver pendência, não decora checkout nem envia novos eventos de marketing. Ao reconectar, repita `revokeConsent()` mesmo com `marketingAllowed() === false`. A pendência sobrevive à recarga da mesma aba; pode ser perdida se o usuário fechar a aba ou se o armazenamento estiver bloqueado. Se o dispositivo estiver offline, o servidor não pode conhecer instantaneamente a revogação: existe essa janela até confirmação ou expiração e ela precisa ser comunicada. Nenhum evento já recebido pela plataforma externa é automaticamente apagado por esta operação.

`reset()` apaga estado local de marketing e **não substitui** a revogação no servidor. Não o use como implementação de opt-out. Ao trocar versão de política, revogue a sessão anterior e obtenha nova escolha antes de retomar.

## Dados, segurança e precisão

- Somente campos allowlisted são enviados: UTMs, `src/sck/xcod`, Meta/Google/Taboola click IDs, `_fbp/_fbc` existentes, consentimento e UUID do evento. Nome/email/telefone não são capturados pelo SDK. Campos arbitrários da URL, fragmentos e credenciais são descartados.
- O backend só persiste origem `/` (não caminhos), protegendo páginas que possam conter IDs pessoais na rota. Dados brutos de campanha/click e contexto de matching ficam privados. No painel, fonte/medium são enums e a campanha só recebe um nome configurado em `campaigns` cujo `external_campaign_id` corresponda a `utm_campaign`. UTMs desconhecidas ficam privadas e não viram rótulos arbitrários no painel.
- IP só é capturado se `PULSO_TRUSTED_IP_HEADER` estiver explicitamente configurado como `cf-connecting-ip` ou `x-real-ip` **após confirmar que o ingress remove o cabeçalho do cliente e o redefine**. `X-Forwarded-For` e IP no corpo são rejeitados/ignorados; padrão sem IP. Sem um header confiável, continua existindo o limite por site, mas não o limite por IP.
- `PULSO_HANDOFF_HMAC_KEY` (mínimo32 caracteres aleatórios) e `PULSO_RATE_HASH_KEY` são segredos exclusivos do backend. Nunca incluí-los no laboratório. SDK não gera `_fbp/_fbc` sintéticos nem tenta fingerprinting.
- IDs de evento são UUIDs criptográficos; retentativas do mesmo evento lógico devem usar `track(name,{eventId:uuidOriginal})`. Nunca reutilize esse ID para outra pessoa/evento ou publicá-lo. Dados privados de sessão têm TTL fixo24h, não estendido implicitamente; o job de retenção precisa ser agendado conforme runbook.
- `Purchase` nunca é emitido no browser por este módulo. Hotmart autenticada confirma a transação; compra server-side reutiliza o event_id estável do backend para retries/dedupe. Não simule Pixel Purchase numa página de obrigado sem contrato de confirmação verificado.

Testes locais: `node --test tests/collector.test.mjs tests/pulso-tracker.test.mjs`. Eles não comprovam entrega Hotmart/Meta nem implantação Supabase.
